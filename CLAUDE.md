# CLAUDE.md — booklib

Локальный веб-каталог библиотеки `/run/media/b/DOWNLOADS/books`: превью на каждую книгу,
разделы по смыслу, клик открывает папку в nemo с выделенным файлом.
Стек: Python + FastAPI + Typer, зависимости через `uv` (`pyproject.toml`), ванильный JS.
Линт и формат — ruff, типы — mypy, тесты — pytest, хуки — pre-commit.

## Железные инварианты

1. **Библиотека строго read-only.** Это активные раздачи qBittorrent (84 торрента):
   переименование или перемещение сломает fastresume-файлы. Никогда не пишем в
   `/run/media/b/DOWNLOADS/books` — ни чистки мусорных `Get More....txt`, ни
   переименований «для порядка». Всё изменяемое живёт в `~/.cache/booklib`.
2. **Диск внешний.** Скан обязан прерваться, если корень не смонтирован или найдено
   0 книг при непустом каталоге (`scanner.LibraryUnavailable`). Без этого одна
   перезагрузка без диска пометит все 353 карточки как missing и сотрёт ручную
   раскладку. Guard проверен мутационно — не ослаблять.
3. **Слушаем только `127.0.0.1`.** `/api/open` запускает процессы в сессии
   пользователя. `BOOKLIB_HOST=0.0.0.0` недопустим.
4. **`X-Booklib` обязателен** для `/api/open`, `/api/rescan`, `/api/book`. Локалхост
   не защищает от чужой вкладки: простой cross-origin POST возможен, а кастомный
   заголовок без CORS-preflight — нет. Preflight мы не обслуживаем.
5. **Путь книги валидируется** на принадлежность корню библиотеки через `resolve()` +
   `is_relative_to()` → иначе 403.

## Как устроено

```
src/booklib/config/settings.py  настройки (env BOOKLIB_*), единственный источник путей
src/booklib/scanner.py          обход дерева → карточки → инкрементальный диф → СУБД
src/booklib/meta.py             нормализация имени файла, название/автор/год
src/booklib/covers.py           превью: pdftocairo / ddjvu+Pillow / zip(epub) / base64(fb2)
src/booklib/taxonomy.py         разделы: overrides → taxonomy.json → rules.json → «Новое»
src/booklib/opener.py           DBus FileManager1.ShowItems, запасной xdg-open
src/booklib/api/app.py          FastAPI + статика в api/static
src/booklib/cli/app.py          Typer CLI, точка входа `booklib`
scripts/build_taxonomy.py       разовая раскладка → config/taxonomy.json (НЕ в git, см. scripts/README.md)
config/rules.json               правила для новых книг
config/taxonomy.json            раскладка (НЕ в git: опись личной библиотеки)
config/taxonomy.example.json    формат + канонический список разделов
tests/{unit,integration}        инварианты из раздела выше
```

Подробнее — `docs/ai-context/architecture.md`.

**Карточка книги** = файлы в одной папке с общим basename после нормализации
(снимаются `.a4`/`.a6` и машинные хвосты `_p117_1`, `_v3`). Одна книга в четырёх
форматах = одна карточка; шесть томов Михайловского = шесть карточек.
Ключ карточки — `относительный_путь_папки/нормализованный_basename`, к нему
привязаны обложка и правки.

**Два слоя правды о разделе:** таблица `books` хранит результат taxonomy, таблица
`overrides` — ручные правки из UI. Выдача склеивает их через `COALESCE`. Поэтому
`taxonomy.json` можно перегенерировать сколько угодно — правки не пострадают.
Не «упрощать» это в одну колонку.

## Грабли, уже собранные (не наступать повторно)

- **`pdftoppm` в poppler 26.07 не пишет jpeg в stdout** — молча даёт 0 байт.
  Используем `pdftocairo -jpeg -singlefile`.
- **`LOWER()` в SQLite умеет только ASCII.** Кириллический поиск без учёта регистра
  требует зарегистрированной питоновской функции `pylower` (см. `api/app.py`, `db()`).
- **Правила `rules.json` матчатся ТОЛЬКО по имени файла**, папка игнорируется
  намеренно: слово `embedded` в имени `programming-embedded/` утаскивало все 136
  файлов этой папки в один раздел. Физической раскладке доверять нельзя — там же
  лежит анархистская литература.
- **Порядок источника обложки ≠ порядок primary_file.** Обложка: epub → fb2 → pdf →
  djvu (в epub настоящая обложка, первая страница PDF часто оказывается схемой).
  `primary_file` для nemo: pdf → djvu → epub → fb2 → rtf.
- **`GROUP BY section` неоднозначен** — колонка есть и в `books`, и в `overrides`.
- **Окно nemo называется именем папки**, а не «nemo». Проверять открытие через
  `wmctrl -l | grep <имя папки>`, иначе покажется, что ShowItems не сработал.
- **`object-fit: cover` калечит альбомные превью** (слайды курсов, даташиты).
  Только `contain` с тёмной подложкой.
- **`pkill -f "<строка>"` убивает сам вызывающий шелл**, если строка встречается в
  его командной строке. Обход: `pkill -f "876[6]"`.

## Команды

```bash
make help                                 # список целей
make fmt lint typecheck test              # перед коммитом
make restart logs                         # systemd --user сервис

uv run booklib scan --dry-run             # статистика без записи в СУБД
uv run booklib scan --show "Эвола"        # как сгруппировались файлы
uv run booklib covers --report            # книги без обложки и причины
uv run booklib sections                   # применить разделы
uv run booklib classify "путь/файл.pdf"   # куда попадёт новая книга
uv run booklib open --dry-run "<ключ>"    # проверить путь, не открывая nemo
uv run booklib doctor                     # утилиты, библиотека, каталог
```

Всё живёт в одном окружении `uv` (`uv sync --dev`). Системный `python3` больше
не используется — Pillow и остальное приходят из зависимостей проекта.

## Как проверять изменения

- Считать «работает» только после просмотра результата глазами: скриншот витрины
  (`google-chrome-stable --headless --screenshot`) или контактный лист обложек.
  Счётчики API не показывают, что превью — нечитаемый обрезок.
- Для guard'ов делать мутационную проверку: вырезать guard из исходника, прогнать
  на копии СУБД и убедиться, что ущерб реально наступает. Первая попытка легко
  оказывается пустой — например traversal-путь может просто не существовать, и
  код упадёт по другой причине, ничего не доказав.
- После правки раскладки прогонять `build_taxonomy.py --check` (локальный скрипт) —
  он падает, если появилась карточка без раздела.
